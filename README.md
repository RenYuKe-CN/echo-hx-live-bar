# Echo HX Live Bar

面向酒吧、餐吧及 Live House 的桌台点单与会员运营系统。仓库包含**顾客微信小程序、收银工作台、服务工作台、管理后台、Node.js API 和 SQLite 数据库**。顾客扫码或选桌点单、加单、兑换团购券及呼叫服务；员工领取配货与配送任务；店主统一管理套餐共用库存、会员、账单、小票打印和跨日营业报表。

当前按单门店运行，暂无多店 / 分店统一管理与数据隔离功能。

> 快速了解能力请看 [项目功能简介](docs/FEATURES.md)，安装请看 [宝塔面板部署教程](docs/BAOTA_DEPLOY.md)。本 README 介绍当前功能、运行要求及业务规则；第三方接口是否可用取决于商户权限、配置和实际联调。

## 系统组成

| 部分 | 入口 / 目录 | 用途 |
| --- | --- | --- |
| 顾客微信小程序 | `miniprogram/` | 扫码或手动选桌、点单与加单、团购券码兑换、呼叫服务、订单和会员服务 |
| 管理后台 | `/admin`，源码 `src/` | 商品与库存、会员运营、桌台账单、打印、营业报表和系统配置 |
| 收银工作台 | `/admin/cashier` | 线下点单、会员充值、交接班、订单与账单查询、团购录入和小票打印，按账号授权展示 |
| 服务工作台 | `/admin/staff` | 接单配货、分批配送、顾客服务需求、个人任务和异常处理 |
| API 服务 | `/api/`，源码 `server/` | 登录权限、服务端计价、订单和库存、支付、数据持久化 |
| 数据与图片 | `data/`（可用 `DATA_DIR` 修改） | SQLite、上传图片和备份文件；不随 Git 更新 |
| 浏览器顾客预览 | 本地 `/` | 开发调试使用；生产 Nginx 配置应让根路径返回 404 |

管理后台由 Vite 构建至 `dist/`，由 Nginx 提供静态文件；Node 服务只处理 `/api/`。**`dist/` 不是微信小程序代码**，微信开发者工具应导入 `miniprogram/`。SQLite 由 Node 依赖读写，无需 MySQL 或单独安装 `sqlite3` 命令行程序。

三个工作台共用账号和业务数据，切换入口不会扩大账号权限。账号配置、提醒、异常召回和部署说明见 [工作台使用说明](docs/WORKDESK.md)。

## 顾客小程序

小程序底部保留“点单”和“会员”两个入口。订单、存酒、充值及兑换从会员页进入。

- **扫码或选桌点单**：扫码或在顶部手动选择就座桌台，使用中的桌台需确认；同桌多人可加入商品，由一人支付当前桌台待购商品，结算后可继续加单。左侧分类可直接点击，右侧连续商品列表滑动时同步高亮分类；商品和组合套餐支持图片、详情、售价、会员价及可售数量。未扫码且未选桌时可浏览菜单，不会默认绑定某张桌台。
- **购物车和确认订单**：增减或移除商品，支付前预览图片、名称、数量、价格、优惠和合计，填写本次订单备注。前后端均限制超库存数量；售罄商品不再作为可下单商品展示。
- **订单与支付**：支持余额、微信及余额加微信组合支付；余额抵扣时优先使用符合规则的赠金，再使用储值金额。创建待支付订单时预占库存及计划使用的余额；可继续支付或取消，10 分钟期限到达后由服务端核对并关闭，确认关闭后释放资源。支付结果不明确时保留待核对状态。付款后进入配货配送，订单卡片整张可点击查看详情与进度，支持未送商品退款申请；隐藏已结束订单不会删除后台记录。
- **呼叫服务员**：扫码或选择桌台后选择呼叫、纸巾、收拾桌面、催单或其他帮助，填写服务备注并查看本桌处理进度；同类未完成请求合并并保留追加内容。
- **团购兑换**：选择美团 / 抖音、粘贴券码、查询固定套餐并确认核销；成功后生成同桌配送订单。不自动读取用户在平台购买的全部券；接口未开通时提示联系服务员。
- **会员档案**：展示头像、昵称、等级、到期日（仅有期限时）、钱包和积分；可查看等级排序、升级条件及到下一级的进度。用户可设置一次阳历或农历生日，之后需由管理员修改。会员资料可在资料设置中后续维护。
- **会员服务**：查看未取完的存酒数量及到期时间；浏览储值套餐和积分兑换奖品。**目前小程序充值页仅展示套餐，线上充值尚未开放；充值请到收银处办理。**
- **券包与消息**：查看后台发放的优惠券、有效期和使用条件，点单结算按规则使用；消息中心展示站内通知，微信订阅消息需要顾客主动授权及有效模板配置。
- **微信资料授权**：`wx.login` 仅换取登录标识，不会自动获得真实头像、昵称或手机号。用户需要点击微信官方头像、昵称和手机号授权组件，授权资料才会保存到会员档案；无法静默读取这些资料。

## 管理后台

后台按账号权限展示功能，主要分为以下工作区：

| 工作区 | 主要能力 |
| --- | --- |
| 经营概览 | 按设置的营业时段统计净销售额、充值及线下收款；查看待送达订单、桌台占用 / 空闲、缺货等提醒 |
| 收银点单、订单管理 | 按桌号与会员点单、选择支付方式；查询商品、备注、付款与退款明细，处理线下收款、退款及单笔小票 |
| 收银交接班 | 开班备用金、现金收支、实盘差异、接班确认；按确认时间归班，保留未完成桌台和配送任务 |
| 服务工作台 | 接单配货、同人配送或吧台配齐后交接、分批送达、顾客需求、个人任务、声音提醒、管理员转交与召回 |
| 桌台账单、小票打印 | 同次开台的点单 / 加单 / 团购归为一张消费账单；打印指定订单或整桌账单，查看任务、核对回执及原版本补打 |
| 桌台管理 | 新增、编辑、删除桌台，生成/下载与桌台 ID 绑定的微信小程序码；保留历史订单关联 |
| 商品与库存 | 基础货品映射组合套餐；配置单位、售价、会员价、进货 / 附加成本、补货线和目标库存；查询货品流水与受影响套餐，按箱补货、预览盘点、导出库存 |
| 会员管理、会员规则 | 按手机号查找和维护会员、余额、积分、等级、到期日、备注和生日；配置等级条件、折扣、有效期及标签颜色，查看今日与近三日生日会员 |
| 存酒管理 | 按手机号定位会员，从现有商品选择存酒与数量，填写存放天数自动计算到期日；取酒后更新剩余数量，仅显示仍有存酒的记录 |
| 储值活动、积分兑换 | 配置储值套餐的实付/储值/赠金金额；设置绑定商品或自定义的积分奖品、所需积分和库存 |
| 优惠券、消息中心 | 配置并发放优惠券，管理消息模板、站内通知、微信订阅消息和发送记录 |
| 赠酒报损、团购核销 | 共用基础货品库存；配置平台固定套餐映射、处理核销异常或商家端核销后录入配送，记录实际结算金额与到账日期 |
| 数据报表 | 按营业日期或精确起止时间查询，配置跨日营业时段与门店时区；查看净销售额、毛利估算、外部收付及多日趋势，导出七个工作表的 Excel |
| 系统设置 | 全局店名、小程序文案和入口图标、接口配置、三级账号与默认工作台、操作日志、备份和恢复 |

角色分为**超级管理员、管理员、店员**；默认工作台与账号级别分别配置。超级管理员可配置接口、账号权限、打印模板、营业规则和备份，并查看报表及审计日志；其他账号按授权访问模块。订单权限同时允许查看桌台账单及打印，服务员默认不读取财务信息。超级管理员可直接修改自己或其他员工的密码，无需旧密码；普通账号修改自己的密码仍需旧密码，重置会注销对应的旧会话。手机号是会员查询与线下操作的主要依据，微信登录不等于已授权手机号。

### 小票与跨日营业报表

小票支持选择某笔订单或整桌消费打印。后台固定配置抬头与末尾的文字、对齐、字号、Logo、小程序码和联系方式；“小票店名”可独立设置，留空时使用账单门店名称，示例预览读取当前店名。正常重复点击返回原打印任务；原件预览及补打使用原内容和模板快照。

飞鹅 FP-V3-WH 使用 **58mm、不带切刀** 配置。标准云接口支持设备预置 Logo 和链接二维码；上传 Logo 后仍需在飞鹅助手预置并在后台确认。也可把上传的小程序码设为唯一预置位图放在票尾。两张不同上传图片同时打印使用浏览器“系统打印完整图片版”，不能当作标准云接口已支持任意图片。真实设备尚需现场试打。

营业日默认按门店时间 **当日 12:00 至次日 06:00**，可修改时区、起止钟点和导出标题，也可单次选择精确范围。Excel 包含当日概览、桌台账单、订单明细、商品明细、收付流水、基础货品流水、会员充值记录，文件示例为 `营业明细-202610131200-202610140600.xlsx`。订单明细在付款人旁列出完整手机号和固定会员 ID，按账号关联，不靠昵称匹配；新订单使用付款时昵称 / 手机号快照，旧订单缺少快照时使用当前会员档案，未绑定手机号时明确标注。手机号、会员 ID 和订单号保留文本格式，金额和时间可筛选；单次最多 31 天、10000 笔订单，超限需缩小范围。

完整配置、统计口径和设备限制见 [小票、账单与营业报表说明](docs/PRINTING-AND-BUSINESS-REPORTS.md)。

新增的退款选择、手动选桌、收银交接班及上线检查，详见 [单门店营业操作说明](docs/SINGLE-STORE-OPERATIONS.md)。经营概览按权限集中提示待核对退款、暂停配送、团购与打印异常，以及备份异常。后台登录加入失败次数限制。

## 关键业务规则

1. **同桌合单与消费账单**：同桌多人加入同一待购清单，付款人按其会员身份结算该次订单。支付后可继续加单；同次开台归为稳定账单号，各子订单保留支付、退款、商品快照和配送记录，不合并支付流水。结束桌台保存最终账单快照；新一轮开台生成新账单。
2. **计价和共用库存**：服务端重新计算售价、会员折扣、优惠券及支付分配。组合套餐按组成数量消耗基础货品，不维护重复的虚拟套餐库存；套餐可售数取组成货品可售数除用量后的最小整数。单品、多个套餐和团购共同校验总需求。支付 / 核销先预占，确认成功后出库，配送不再次扣库存；结果未确认时不盲目释放。
3. **会员等级**：后台可配置不同等级的储值金额和累计消费升级门槛、条件组合、折扣、积分比例、有效期及标识颜色；到期、续期和降级按后台规则处理。普通会员可看到会员价格提示，但实际结算不冒用会员优惠。
4. **销售与收款分账**：储值本金和赠金分账记录，赠金不计净销售额。报表将消费结算、余额内部扣减、充值收款、团购核销记账和平台实际到账分开。付款按确认时间、退款按完成时间归属营业时段；只有实际退库才冲回相应成本，无法明确的历史成本 / 毛利留空并提示。商品毛利估算未扣房租、人工和未记录的平台费用，不代表净利润。
5. **订单履约**：线上订单支付成功后进入服务工作台，领取配货、按本批数量出货，由唯一配送负责人确认实际送达；所有应送商品处理完后整单完成。顾客订单同步显示配货和配送进度。待支付订单有 10 分钟期限，顾客可以继续支付或取消。微信支付最终状态以服务端查询及经验证的回调为准，不能仅凭小程序页面提示认定成功。
6. **存酒**：按商品数量存取，不逐瓶扫码；到期日由登记时刻和存放天数计算。取完的存酒不再列入顾客和后台当前存酒列表，但历史业务数据保留。
7. **防漏单与重复处理**：配货、配送和服务需求有唯一负责人及持久化事件提醒，管理员转交需留原因。未完成订单、服务需求、待确认团购或处理中退款会阻止结束桌台。打印超时保留待核对，不自动重复发送；人工核对与平台确认分别显示。

## 第三方接口状态与边界

| 能力 | 当前代码 / 上线要求 |
| --- | --- |
| 微信登录及资料 | 已有小程序 `wx.login`、服务端登录和手机号授权接口；真实头像、昵称、手机号仍须用户按微信官方组件操作。须配置同一小程序的 AppID/AppSecret 并联调。 |
| 微信支付 | 服务端已有 API v3 JSAPI 下单、支付查询、回调验签/解密及混合支付流程；上线须配置真实商户号、API v3 Key、商户私钥及证书/公钥、HTTPS 回调地址，并完成实际商户环境联调。不要将未联调状态当作已可收款。 |
| 桌台小程序码 | 通过微信官方 `wxa/getwxacodeunlimit` 生成；须有有效小程序凭证，并确保目标页面 `pages/menu/menu` 存在于所选 `develop`、`trial` 或 `release` 版本。 |
| 美团券码核销 | 已实现餐饮品牌直连 `businessId=79` 的查券、预核销、单张固定套餐核销及原订单历史核对；默认关闭，需直连凭证、门店与 SKU 绑定、场景权限确认及实券联调。没有接入自动读取用户全部已购券的 OAuth 流程。详见 [美团接入说明](docs/MEITUAN-REDEMPTION.md)。 |
| 抖音券码核销 | 已实现明文券码验券准备及单张固定团购套餐核销；默认关闭，需商家授权、核销权限、门店配置及实券联调。两平台均保留商家端核销后录入配送，结果不明确时不模拟成功。详见 [套餐与团购说明](docs/CATALOG-AND-GROUP-BUY.md)。 |
| 飞鹅打印 | 已实现设备绑定、状态查询、签名打印、分段回执、异常核对和原件补打，使用迁移后的独立 HTTPS 接口；需 USER / UKEY、设备 SN / KEY、启用开关及真实出纸验收，当前验证使用模拟接口。图片范围见上文。 |
| 图片存储 | 默认写入本地 `data/uploads/`；可配置 S3 兼容对象存储用于**后续新上传**文件。已有本地图片不会自动迁移，远端对象不包含在本地备份内。 |

后台“接口配置”可填写部分配置；服务器环境变量优先于后台配置。密钥只放服务器或受控后台，**不要写入小程序源码、README 示例真实值或 Git 仓库**。配置完整不等于平台权限已开通，正式收款与团购核销必须在对应平台完成验收。

## 目录与运行要求

```text
miniprogram/     微信小程序源码及独立使用说明
src/             管理后台和本地网页预览源码
server/          Express API、SQLite 数据与外部接口
scripts/         安装、更新、服务管理、备份脚本
deploy/          Nginx 配置示例
docs/            功能简介、工作台、套餐 / 团购、打印 / 报表和部署说明
data/            运行时数据库、上传图片和备份（不提交 Git）
dist/            npm run build 生成的网页静态资源（不上传微信）
```

需要 Node.js **22 或 24**（当前 SQLite 依赖要求 Node.js 22+）、npm、Git；服务器建议使用 Nginx 和 HTTPS。生产环境只让 Nginx 对外提供 443，API 默认监听 `127.0.0.1:3001`；Node 进程必须拥有 `data/` 的读写权限。

### 本地开发

```bash
npm ci --include=dev
cp .env.example .env   # 已存在 .env 时不要覆盖
npm run dev
```

默认预览地址：顾客网页 `http://localhost:5173/`，后台 `http://localhost:5173/admin`，健康检查 `http://127.0.0.1:3001/api/health`。本地预览不等于微信开发者工具真机环境；小程序请按 [小程序说明](miniprogram/README.md) 导入 `miniprogram/` 并配置合法域名。

API 启动会自动读取项目根目录的 `.env`，进程管理器传入的同名变量优先；可用 `ECHO_ENV_FILE` 指定其他配置文件。`npm run dev` 明确使用开发模式，`npm start` 和直接运行 `server/index.js` 使用文件或进程提供的 `NODE_ENV`。

运行 `npm test` 可验证支付与退款、桌台权限、服务和分批配送、套餐共用库存、团购核销恢复、打印去重 / 补打、跨日 Excel 报表、小程序滚动联动和旧备份升级。GitHub Actions 在 Node.js 22 和 24 上执行测试及前端构建；测试使用临时数据库与模拟微信、团购及飞鹅响应，不访问真实商户或打印机。

### 宝塔部署（推荐）

完整操作和 Nginx 配置见 [宝塔面板部署教程](docs/BAOTA_DEPLOY.md)。最短路径：

1. 宝塔安装 Node.js 22/24、Nginx、Git，配置域名解析和 HTTPS。
2. 克隆仓库到 `/www/wwwroot/echo-hx-live-bar`，在项目目录运行 `bash scripts/manage.sh install`；它会检查 Node、安装锁定依赖、创建未存在的 `.env` 并构建 `dist/`。
3. 配置 `.env`；宝塔“Node 项目”以项目根目录为工作目录运行 `server/index.js`，启动时自动读取根目录 `.env`，监听 3001；**只使用宝塔托管这一套进程**。
4. 宝塔站点根目录指向 `dist/`，将 `/api/` 反向代理到 `http://127.0.0.1:3001`，保留 `/admin` 及 `/assets/`；根路径 `/` 返回 404，禁止通过网页顾客预览下单。
5. 验证 `https://你的域名/api/health` 返回 JSON、`/admin` 可登录、`/` 返回 404；再配置小程序和支付。

`bash scripts/manage.sh update` 默认只同步 GitHub `origin/main`，更新前备份业务数据库以及服务器本地代码改动，然后安装依赖、构建。**宝塔默认 `MANAGE_SERVICE=panel`，更新后须到宝塔 Node 项目手动重启。**更新以远程 `main` 为准，会替换服务器上直接改过的跟踪文件；不要把生产服务器当作开发工作区。数据库迁移可能不可逆，回退代码前先保留数据备份。

### 非宝塔部署

以 `/var/www/echo-hx-live-bar` 为示例目录：安装 Node.js 22/24、Git、Nginx，克隆后运行 `bash scripts/install.sh`，配置 `.env`，使用一种持久进程管理方式运行 Node API，并以 [Nginx 示例](deploy/nginx.conf.example) 提供 `dist/` 和 `/api/`。仅使用脚本管理进程时可执行 `bash scripts/service.sh start|stop|restart|status`；**不要与宝塔 Node 项目或其他进程管理器同时启动**。HTTPS 证书与域名须自行配置。

### 环境变量与小程序合法域名

首次安装复制 `.env.example` 为 `.env`。至少设置强密码 `ADMIN_INITIAL_PASSWORD`、`NODE_ENV=production`、`HOST=127.0.0.1`、`PORT=3001` 和正式 `MINIPROGRAM_API_BASE_URL=https://你的域名/api`。首次后台账号为 `admin`；如未提供初始密码，查看 API 启动日志中的随机密码，登录后及时修改。

微信支付平台证书的序列号由服务端解析；若配置的是 PEM 公钥，则必须同时填写对应的 `WECHAT_PLATFORM_SERIAL`，可在服务器环境变量或后台“接口配置”中设置。退款回调使用 `https://你的域名/api/payments/wechat/refund/notify`，可通过 `WECHAT_REFUND_NOTIFY_URL` 单独指定；留空时从支付回调地址推导，避免退款通知进入支付接口。

支付或退款请求超时不代表失败。服务端保留待核对状态和必要的预占资源，定时查询退款、关闭过期支付；退款重试沿用原退款单号。待支付微信订单不能直接改为线下已收款，若改用现金或商家收款码，请先取消微信订单再通过收银台重新下单。

**API 基础地址包含 `/api`；微信公众平台的 request、uploadFile、downloadFile 合法域名只填 `https://你的域名`，不得带 `/api` 或接口路径。**在后台修改运行时 API 地址后，小程序仍需要能访问原来的引导地址；更换域名时新旧域名都应加入微信合法域名并验证。正式小程序须在微信开发者工具中使用真实 AppID，上传并发布相应版本。详细授权、支付及图片域名设置见 [小程序说明](miniprogram/README.md) 与 [宝塔教程](docs/BAOTA_DEPLOY.md)。

## 备份、迁移与版本管理

超级管理员在“备份与恢复”可手动备份、下载 `.tar.gz`、设置每日/每周自动备份及上传恢复。自动任务依赖 Node API 持续运行。可用 `BACKUP_MIRROR_DIR` 指向已挂载的私有远程目录，每次备份完成后复制并校验副本；需要目录标识文件，复制失败保留本地成功文件并提示，详情见宝塔部署说明。也可以运行 `bash scripts/backup.sh`；文件保存于 `data/backups/`。恢复前会保留当前数据的安全副本，完成后重新登录并核对商品图片、会员和订单。

备份包含 **SQLite 数据库和本地 `data/uploads/` 图片**，不包含 `.env`、远端对象存储文件和 Node 依赖；备份中的第三方密钥与登录会话会移除。更换服务器时先安装相同版本代码、设置 `.env` 与 HTTPS，再从后台上传备份，重新填写微信支付、团购、飞鹅及对象存储密钥。打印机设备 KEY 与绑定状态也会移除，恢复后的未完成任务须核对出纸情况，不自动重发。后台账号密码随数据库保留，但登录会话失效。备份仍含敏感经营和会员数据，应加密或受控保存到服务器之外。对象存储需另行备份。

```bash
bash scripts/manage.sh version   # 当前及本地记录的远程版本
bash scripts/manage.sh history   # 最近 10 次提交
bash scripts/manage.sh status    # 进程提示与 API 健康检查
bash scripts/manage.sh update    # 更新 origin/main；宝塔托管需手动重启 Node 项目
```

若服务器上有直接编辑的代码，更新脚本会把本地差异保存到 `backups/update-时间/`，但后续运行以 GitHub `main` 为准；业务配置 `.env` 和 `data/` 不随 Git 覆盖。不要提交 `.env`、`data/`、`backups/`、数据库、图片或支付私钥到 GitHub。

退款回库会记录订单商品的实际退回数量，利润仅冲回已回库商品的成本；新退款默认不回库，已消费退款保留成本，可按基础货品选择部分回库，送达后实物退回也单独记录。旧数据库或旧备份首次升级时会补录可确认的历史回库数量，不再次修改库存。若旧版本已经造成重复回库，需要对照库存流水和实物盘点人工修正，升级不会自动改写这部分历史库存。

## 上线检查

- `node --version` 为 22+；构建成功且 `dist/index.html` 存在；Node 进程可读写 `data/`、`logs/`。
- HTTPS 下 `/api/health` 返回 JSON、`/admin` 可登录、网站 `/` 返回 404；3001 不对公网开放。
- 管理员已修改初始密码、分配最小权限；商品图片、库存和桌台码可正常访问。
- 小程序使用正确 AppID，request/uploadFile/downloadFile 域名和版本配置正确；头像昵称手机号经过真实授权流程验证。
- 微信商户参数、回调域名、订单支付/取消/超时及退款等营业相关流程完成真实环境验证；未经联调不投入真实收款。
- 使用美团 / 抖音时确认商户权限、套餐映射并完成实券联调；内部录入不能代替官方核销。
- 使用飞鹅时确认账号、设备绑定、58mm / 切刀规格、预置图片、二维码扫码和实际出纸结果；营业报表起止时间与门店营业安排一致。
- 已从后台下载备份并在测试环境演练恢复；确认远端图片另有备份及新服务器可重新配置密钥。

常见问题：`vite: command not found` 通常是未安装开发依赖，运行安装脚本；`Unexpected token '||='` 通常是 Node 版本过旧；接口返回 HTML 而非 JSON 时检查 Nginx `/api/` 反向代理；图片 404 时检查 `/api/product-images/` 是否被 Nginx 静态规则截获、上传目录权限和历史图片是否迁移。更多操作细节见 [宝塔教程](docs/BAOTA_DEPLOY.md)。
