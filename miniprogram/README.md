# Echo HX Live Bar 小程序

顾客端支持扫码或手动选桌点单与加单、共享购物车、微信 / 余额 / 组合支付、团购券码兑换、呼叫服务员、订单和配送进度，以及会员等级、存酒、积分兑换、券包与消息。完整系统能力见 [项目功能简介](../docs/FEATURES.md)，员工、库存、账单和打印在对应后台处理。

点单首页与会员页采用米白、深绿和暖铜色，保留原生顶部导航与“点单 / 会员”两个 Tab。商品图片使用后台上传的图片，无图或加载失败时显示统一的线条图标；会员页分别展示储值、赠金和积分，不合并为一个余额。

所有面向顾客展示的店名均来自后台“系统设置 → 小程序页面 → 店铺名称（全局展示）”，包括主页面导航、会员卡、授权提示和资料设置；管理后台也使用同一名称。微信搜索结果中的小程序正式名称仍由微信公众平台管理。后台入口标题与图标继续可配置。

更新服务器不会自动发布小程序样式。代码更新后，须在微信开发者工具中重新编译、预览并上传 `miniprogram/`，再发布对应版本；后台修改店名和入口配置则无须重新上传，顾客下次打开或切换主页面时会读取最新设置。

扫码或手动选桌并确认后，顾客可点击桌号旁的“呼叫服务员”，选择服务类型并备注需求，查看本桌处理进度；同桌重复呼叫合并，其他帮助须填写具体内容。未扫码且未选桌时仅浏览菜单，不默认绑定 A-08。点击顶部“选择桌台 / 桌号 · 切换”可选择当前就座桌台：三列桌卡、顶部搜索桌号及全部 / 空闲 / 使用中筛选，桌卡区域独立滚动，便于查找三四十桌。输入 `A08` 可查找 `A-08`，使用中的桌台需要确认。切换时可保留或仅移动自己的未下单商品；待支付订单须先支付或取消。已付订单、团购兑换和服务需求仍在原桌，需要调整配送位置时联系服务员。员工使用自己的后台账号进入 `/admin/staff` 处理服务及离店清台，清台沿用服务工作台权限，详细说明见 [工作台使用说明](../docs/WORKDESK.md)。

用微信开发者工具打开本目录：

```text
项目目录/miniprogram
```

如果打开的是上一级项目目录，也可以使用项目根目录的 `project.config.json`，两种打开方式都已配置。

当前引导 API 地址为 `https://www.9bar.cn/api`；连接本地测试服务时，先将 `utils/api.js` 中的 `BOOTSTRAP_API_URL` 改为 `http://localhost:3001/api`，发布前恢复正式 HTTPS 地址。电脑端预览请在微信开发者工具中关闭“校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”；真机调试需要可访问的 HTTPS 域名，并在正式发布前配置 request 合法域名。小程序启动时会从引导 API 读取后台的 `public_api_base_url`；读取失败时回退到引导地址。

微信登录流程已经接通：小程序调用 `wx.login` 获取临时 `code`，后端使用超级管理员后台配置的 AppID/AppSecret 调用微信 `jscode2session` 换取 openid，再创建登录会话。若登录失败，小程序会显示微信接口返回的错误信息，不会静默使用演示用户。

首次进入首页会在当前页面显示授权弹层，不会跳转到另一个资料页面。头像和昵称使用微信当前官方组件：点击 `button open-type="chooseAvatar"` 选择头像，使用 `input type="nickname"` 填写昵称；保存后再点击 `button open-type="getPhoneNumber"` 完成手机号授权。该头像、昵称组件要求微信小程序基础库至少为 `2.21.2`；手机号按钮事件返回的一次性 `detail.code` 只能立即发送给后端，不能使用 `wx.login` 的 code 代替。后端把三项信息保存到同一个会员账户的 `avatar_url`、`nickname` 和 `phone` 字段，后台“会员管理”可按手机号查看。`wx.login` 只负责登录换取 openid，不会直接返回头像、昵称或手机号；小程序也不会在用户没有点击官方组件时静默读取这些资料。会员页仍保留“资料设置”入口，用于后续主动修改头像和昵称。手机号授权使用微信官方 `getuserphonenumber` 接口，因此线上必须配置正确的 AppID/AppSecret，并在小程序隐私设置中声明头像、昵称、手机号的用途。

头像上传使用 `wx.uploadFile` 请求 `/api/me/avatar`，商品图片上传使用后台的 `/api/admin/products/image`。两个接口会把文件默认保存到服务器 `data/uploads/`；如果超级管理员配置了 S3 兼容对象存储，则新文件会切换到对象存储。微信公众平台需要将 API 的同一个 HTTPS 主域名分别加入 request、uploadFile 和 downloadFile 合法域名，填写域名时不要带 `/api` 后缀。开发者工具本地调试可关闭合法域名校验，真机和正式版必须使用备案/证书正常的 HTTPS 域名。

本地验证步骤：

1. 启动 API：`npm run dev` 或 `node server/index.js`。
2. 用微信开发者工具打开本目录，确认 AppID 与 `miniprogram/project.config.json` 中的 AppID 一致。
3. 在工具设置中关闭合法域名校验，重新编译小程序。
4. 在超级管理员后台的“接口配置”填写 AppID 和 AppSecret；如只做本地开发，也可以暂时不填写正式 HTTPS API 地址。
5. 查看开发者工具 Console 和 Network。`POST /api/auth/wechat/login` 返回 `200` 且有 `token` 才表示登录成功。

如果返回 `40013`，通常是 AppID 或 AppSecret 不匹配；返回 `40029` 是 code 无效或重复使用；如果请求失败，则检查 API 服务、开发者工具合法域名校验和 `http://localhost:3001/api/health`。

支付按钮会创建待支付订单并调起微信支付，收到客户端成功回调后仍会查询服务端状态，确认到账才显示“支付成功”；暂未确认时显示“支付状态核对中”。真实微信支付须配置商户号、AppID、API v3 密钥、私钥、平台证书或公钥及 HTTPS 回调，并完成商户环境联调。使用公钥时须同时设置对应的 `WECHAT_PLATFORM_SERIAL`（`PUB_KEY_ID_` 开头）。

## 分类点单与团购兑换

点单页为左侧分类、右侧连续商品分组。点击分类平滑定位，右侧滑动同步高亮左侧；购物车更新只修改对应字段。仍使用 WebView，右侧和分类栏使用独立 scroll-view。

点单页“团购兑换”支持粘贴券码、查询固定套餐、确认兑换及查看配送订单，需要先扫码或选择桌台。平台未开通时显示待开通并可呼叫服务员，不生成模拟成功订单。组成货品、成本与库存规则见 [套餐与团购说明](../docs/CATALOG-AND-GROUP-BUY.md)。

美团已实现餐饮品牌直连查券、预核销、单券核销和原订单历史核对，配置见 [美团接入说明](../docs/MEITUAN-REDEMPTION.md)；抖音已实现券码准备及验券。两平台自助开关默认关闭，启用前须完成商户授权 / 权限确认和实券联调。当前输入券码兑换，不读取平台账号全部已购券，不支持代金券、次卡或多选套餐。

套餐与单品共用基础货品库存，显示的套餐可售数由组成数量计算。顾客支付 / 核销后，服务工作台按实际货品配货和分批配送；点按整张订单卡片可查看订单详情。继续加单保留独立订单，后台同时归入当次开台账单，可统一打印小票。会员充值页目前展示活动套餐，线上充值尚未开放，由收银处办理。

新增小程序功能时同步更新本说明及项目 README / 功能简介，文档与源码一起发布；服务器更新不会自动替代微信小程序上传和发布。

桌台选择、切换保护与已付订单归属见 [单门店营业操作说明](../docs/SINGLE-STORE-OPERATIONS.md)。本版仍为单门店；多门店和跨店余额未实现。


## 套餐订单商品汇总

订单详情的商品清单按基础货品 ID 与下单单位合并显示数量，相同货品不再因套餐金额尾差显示多条 ×1。套餐明细保留套餐名称与数量，基础货品显示合计数量、送达 / 退款进度及准确金额小计；同一货品包含不同价格时不展示一个虚构的平均单价。不同商品即使同名也不合并。

顾客按合并后的商品选择退款数量，系统映射到原始订单明细计算金额；已送达、赠品及原退款限制继续生效。后台订单、配货输入、每批配送及退款货品处理也按相同规则汇总。此次修改涉及订单详情 JS / WXML，须另行编译、上传和发布小程序，更新服务器不会自动更新顾客端页面。
