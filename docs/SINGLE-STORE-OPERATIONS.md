# 单门店退款、选桌与交接班

本版继续按单门店运行，不增加多门店、直营 / 加盟管理或跨店余额。

## 退款和货品处理

入口仍为“订单管理 → 退款 / 审核退款”。超级管理员始终可处理；管理员或店员需同时拥有“订单管理”和“退款处理”权限，才能主动退款、同意或拒绝顾客申请及查询退款结果。只授权订单管理时仍可查看订单中的退款状态和原因，但不显示退款操作按钮，接口也拒绝操作。顾客仍只能申请未送达的付费商品退款；已消费后的补偿由获授退款权限的人员填写金额与原因。

超管在“系统设置 → 账号管理 → 编辑权限”勾选“退款处理”，须先勾选“订单管理”。新建账号不默认授予退款权限。首次升级会给已有且具有订单权限的管理员补上该权限，以保留原能力；普通店员不自动获得。此迁移只执行一次，之后取消授权不会在重启时恢复；恢复旧版备份时也会执行兼容迁移。权限变更后目标账号刷新页面或重新登录以更新菜单和按钮，服务端对现有会话立即校验；退款权限不授予报表、成本、利润、人员设置或服务任务转交权限。

订单列表将原字段分成订单信息、付款人、商品与备注、金额汇总、优惠与支付、退款信息、操作七组，金额和优惠 / 支付分开排列，并收紧单元格间距与行高。桌号、状态、完整手机号、全部商品与备注、原价和各项优惠、实付、净销售额、利润及退款原因均保留，利润仍按原权限展示。完整订单号换行显示并可点击复制；电脑宽屏为七列，较窄内容区域转为分区排列，长内容自动换行，不隐藏在详情页或截断。退款、小票和配送按钮仍在订单的操作区，其他列表不变。

订单顶部的“付款人手机号”支持完整号码或部分数字（1～11 位，如后 4 位），点击“查询订单”或回车查询全部历史订单，不限当前页。筛选与分页使用同一条件，查询或清空会回到第一页，翻页、刷新及处理退款后保留已应用条件；“清空”恢复全部订单。输入期间不会被订单定时刷新打断，未提交的输入不会改变当前结果。新订单匹配付款时保存的手机号，不随后来改名或更换手机号改变；旧订单缺少快照时匹配当前会员手机号，已记录“未绑定”的快照不会用后来补绑的手机号覆盖。搜索不按同名顾客、同桌成员或其他联系方式匹配，也不额外授予退款权限。

退款金额、停止配送、回库数量分别记录：

- 默认“退款不回库”，适用于已开瓶、已制作、已消费或无法再次销售的货品。退款成功后不增加库存、不冲回成本，也不再记一次相同货品的报损。
- 选择回库时，逐项填写可再次销售的基础货品数量，并勾选实物确认。套餐按原订单展开的基础货品处理，可只退回其中一部分；不使用后来修改的套餐配方。
- 全额退款自动停止尚未送达的全部数量。部分退款按顾客申请明细或管理员填写的“本次停止配送”数量处理；仅按金额补偿、未选择停止数量时，剩余配送继续。
- 已送达但未开封、已实际收回的货品也可回库；保留原配送历史，单独记录送达后回库数量。已停止配送但未回库的数量不会重新进入待配队列。
- 配送在途须先核实实际送达或由管理员核实召回；处理中的退款继续阻止配送。相关待取批次取消后，其余未退款数量重新待配。
- 线下退款必须确认已按原渠道实际退付，软件不会代替现金交付或商家收款码平台退款。
- 同一次后台直接退款使用固定请求编号，重复点击 / 断网重试返回原记录；修改金额、原因或货品处理后不能复用旧编号。微信结果未确认时沿原退款单查询，不重新创建退款。

例如销售 100 元、成本 30 元的酒已消费后全退：净销售额为 0 元，成本仍为 30 元，商品毛利估算为 −30 元，库存不增加。只有实际回库的成本才在退款完成时冲回。

团购先在原平台办理整券撤销或退款，再在“团购核销”填写平台凭证及原因，同步本地订单。可选择不回库或按货品数量回库；不直接调用余额 / 微信订单退款接口，不支持平台部分退款自动分摊。在途配送仍须先核实。

升级前已发起、尚在处理的退款保留原来授权的库存处理方式；升级后的新退款默认不回库，不改写已成功历史记录。

## 顾客选桌与切换

点单页顶部点击“选择桌台”或“桌号 · 切换”，也可扫码进入。选桌弹层采用三列桌卡，顶部搜索与状态筛选固定，列表独立滚动；三四十桌不用铺满整个点单页。支持输入 `A08` 查找 `A-08`，按桌号自然顺序排列，可筛选全部、空闲、使用中。列表只显示桌号及空闲 / 使用状态，停用桌台不显示；列表不包含顾客资料、消费金额或订单。选择使用中的桌台须确认已在此桌就座，确认后加入本桌共享购物车和桌台订单，无须每次由员工审批。

切换时可保留自己的未下单商品在原桌，或只移动自己的未下单商品到新桌；他人的购物车不移动。服务端重新检查目标桌总库存，结算按实时价格与会员规则计算。原桌的已支付订单、团购兑换、服务需求及账单保持原归属。

原桌存在自己的待支付订单时，须到“我的订单”支付或取消，确认结果后才能切换。付款进行中不允许前端切桌，旧请求迟到不覆盖新桌购物车。回库、团购核销和支付结果始终关联原订单。

本功能改变后续点单桌台，不会自动搬移已付订单或合并两桌账单。已付商品需要调整实际配送位置时，请先联系服务员核实协调。

## 服务员离店清台

服务员在原有服务工作台进入“桌台清台”，完成现场打扫、确认客人离店后结束本桌，无须新增权限。可搜索桌号、筛选使用中或可清台桌台；系统会拦截待支付、待送达 / 在途配送、未完成服务、待确认核销及待审核 / 处理中退款。未下单商品只作提示，确认结束后不能继续结算本次清单。

结束操作保留历史订单和最终账单，下一批顾客建立新开台账单。请求绑定原开台编号，防止旧页面或重试误关下一桌顾客。详细操作见 [工作台说明](WORKDESK.md#桌台清台)。

## 收银交接班

入口在“收银与订单 → 收银交接班”，沿用“收银点单”权限；不因此开放超级管理员经营报表。门店共用一个现金钱箱、同一时间只有一个进行中的收银班次，多收银台独立钱箱不在本版范围。

1. 当班收银员登录自己的账号，点击“开班并登记备用金”。首次开班启用交接班控制，之后未开班时不能登记现金收款 / 现金退款；升级不会自动替门店开班或归入旧流水。
2. 现金订单收款、现金充值和现金退款自动记账。其他现金收入、支出、缴存或补充备用金由当班人员登记，必须写原因；它们只影响钱箱，不增加商品销售额。
3. 点击“开始交班盘点”，现金收款、现金充值与现金退款暂停。微信、储值、商家收款码等非现金业务继续；在线确认仍归当前班次。
4. 填写实盘现金；有长短款时必须填写原因，也可说明待交接事项。提交后等待另一名有收银权限的账号登录确认接班。
5. 接班确认在一个数据库事务内结束旧班并开启新班，实盘现金作为新班备用金，之后确认的交易归新班。同一接班请求重试不会再开一班。无接班人、当日结束营业时可选择“结束班次”，下一次现金业务须重新开班。

应有现金 = 开班备用金 + 现金订单收款 + 现金充值 + 其他现金收入 − 现金退款 − 现金支出 / 提走现金。

微信、商家收款码、储值本金、赠金、团购核销记账、团购实际结算分别列示，不相加当作同一项收入。班次按系统确认时间归属；团购实际到账日仍按营业报表录入日期统计。晚付款订单、跨班退款归实际确认班次，并保留原单关联。未开班时的非现金交易单列“未归班流水”，不补记进后来班次，也不从营业报表中消失。

交班不结束桌台、不清空购物车、不重置配货或配送负责人。页面列出待配送、服务和退款数量，员工在服务工作台继续处理；需要转交时由管理员核对实物后使用已有转交流程。

页面显示最近 50 个已结束班次，每个班次详情最多显示最近 1000 条流水，汇总按全部流水计算。默认保留所有班次数据，不自动修改历史盘点结果。

## 身份追溯与异常提醒

新付款订单保存付款时手机号及昵称，同时保留固定会员 ID；之后修改资料不改变付款快照。旧订单缺少快照时仍使用当前会员资料，无法据此还原过去未保存的手机号。订单后台及 Excel 按该规则展示；顾客小票不包含完整手机号。

经营概览按账号已有模块权限提示退款待确认、配送暂停、团购待核对和打印异常，超级管理员还可看到近期自动备份缺失与外部副本复制失败。提醒不会代替人工核对，也不会自动重发打印或退款。

后台登录按账号限制 10 分钟内 10 次失败，按服务看到的来源 IP 限制 50 次失败，达到限制返回 429；过期恢复，状态保存在数据库中。默认不信任浏览器传入的代理 IP 头，同一 Nginx 代理后的客户端可能共用 IP 限额。

操作日志支持按时间、关键词查询并导出 Excel，超级管理员核对本地文件后可清理本次已导出的日志，订单及资金数据不受影响。存储口径、权限和清理限制见 [操作日志说明](OPERATION-LOGS.md)。

## 验证范围

代码测试使用独立临时数据库与模拟响应，覆盖退款成本与库存、重复请求、旧库迁移、选桌及购物车隔离、现金盘点、接班、支付身份快照和备份复制。微信真机、真实支付退款、平台实券、实际打印机和服务器远程备份挂载仍须现场联调，不能以自动测试代替真实验收。
