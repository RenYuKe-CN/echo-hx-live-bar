# 收银、服务与管理工作台

三个入口共用现有账号、订单和数据库：

| 入口 | 用途 | 默认权限 |
| --- | --- | --- |
| `/admin` | 管理后台，商品、会员、账务和人员设置 | 按原账号授权；店主超级管理员拥有全部模块 |
| `/admin/cashier` | 收银工作台，点单、充值、交接班、团购、账单查询和打印 | 收银点单、订单管理、团购核销；账单与打印沿用订单权限 |
| `/admin/staff` | 服务工作台，配货、配送、顾客需求及离店清台 | 服务工作台 |

这些地址沿用宝塔现有 `/admin/` 的静态路由，无须为了员工入口另建站点。Nginx 示例还提供 `/staff`、`/cashier` 短地址；只有配置了对应短地址的站点才能直接使用它们。更新代码不会自动修改宝塔 Nginx 配置。

## 创建员工账号

店主进入管理后台的“系统设置 → 账号管理”，新增或编辑员工：

1. 填写个人登录账号、显示名称和初始密码。
2. 服务员、收银员选择“店员”账号级别；需要审批和转交权限的店长选择“管理员”级别。
3. 选择默认工作台：服务员、收银或管理后台。选择后会填入相应模块预设，可以额外授权兼任业务。
4. 每位员工使用自己的账号；首次登录后在工作台修改自己的密码。

现有账号保留原权限，不会因更新自动扩权。现有服务员需要在账号管理中授权“服务工作台”；原店长若要监督、转交任务，也需有此模块权限。切换工作台不会改变实际权限，服务员默认不能读取收银或财务订单接口。

超级管理员可直接设置管理员 / 店员密码，无需目标账号的原密码，目标账号旧会话会注销。超级管理员修改自己的密码也无需旧密码，保留当前会话并注销其他设备；普通员工修改自己的密码仍须验证原密码。操作记录保存在后台日志中。

## 顾客呼叫服务

顾客扫码或手动选择桌台并确认后，点单页桌号旁会出现“呼叫服务员”。可以选择呼叫、纸巾、收拾桌面、催单或其他帮助，填写最多 300 字备注；其他帮助必须填写内容。

- 未扫码且未选桌时可以浏览菜单，但不会默认绑定 A-08 桌，也不能提交订单或服务请求。
- 同桌同类未完成请求合并，追加呼叫次数和每次备注会保留并提醒处理人；网络失败后的同一次重试不会重复派单或增加次数。
- 服务请求不生成收费商品订单，不扣库存或钱包；购买商品仍需通过菜单或收银下单。
- 顾客可查看本桌近期服务记录、处理人和处理说明。服务员完成后，顾客端在页面前台定时更新状态。

## 配货与配送

已付款订单进入待接单队列，待支付订单不会进入配送。服务员点击“接单配货”后自动进入“我的任务”。

- **同一人完成**：接单配货 → 填写本批应配数量 → 配齐并配送 → 核对桌号、批次与商品后确认实际送达。
- **吧台与服务员分工**：吧台接单配货 → 配齐待取；服务员领取配送 → 确认实际送达。
- **分批送达**：本批数量可以少于待配数量；每一批有独立编号和配送负责人。工作台分别展示原订、已送、已停止、已回库、待配，配送时按“本批商品”清单带货。
- 同一批只能由一个负责人领取；重复点击或重试不会重复计入送达数量。完成当前任务后，没有其他个人待办时，会自动回到下一类待接队列。
- 原订单管理页面用于账务和退款查询，实际送达统一在服务工作台确认。

## 顾客需求处理

“顾客服务”展示待响应、处理中和已完成请求，工作人员也可在“我的任务”中一起查看已领取的订单和顾客需求。

领取需求 → 到桌边处理 → 填写可选处理说明 → 点击“处理完成”。如果处理期间顾客新增了备注，服务器会要求核对更新后的内容再完成，避免遗漏补充需求。

## 桌台清台

直接进入服务工作台的“桌台清台”，沿用现有“服务工作台”权限，不设置独立清台权限，也不开放账务模块。列表只显示桌号、业务待办数量及未下单商品数量，不提供消费金额、付款人手机号。

1. 按“使用中 / 可清台 / 全部”筛选，或搜索桌号；“可清台”仅表示系统待办已处理完，仍须现场确认客人离店。
2. 服务员收拾桌面后点击“清台并结束本桌”，勾选“我已确认顾客离店，并完成桌面清理”，再确认结束。
3. 待支付订单、待送达订单、待取 / 在途配送、未完成服务、结果待确认团购核销、待审核 / 处理中退款都会阻止结束。先完成相应任务，涉及钱款或平台结果时联系收银 / 管理员核对。
4. 如有未下单商品，弹窗明确提示结束后本次清单不能继续结算。原订单、支付和退款记录保留，保存最终桌台账单；下一批顾客扫码或选桌时建立新账单。

清台请求绑定本次开台编号；重复点击或断线重试不会重复结束，也不会误关重新开台后的另一批顾客。服务器确认成功后，该桌变为空闲，并记录实际操作员工。已有服务工作台账号直接可用，无须额外授予“桌台管理”。

## 提醒、断网与异常

- 工作台每 3 秒同步任务，使用持久化事件序号识别新单、新配齐批次及补充需求，不依赖待处理总数增减。旧订单晚付款也会产生新单事件。
- 首次使用须点击“开启声音提醒”。保持工作台在前台，浏览器后台或手机休眠不保证声音与刷新持续运行；这不是微信锁屏订阅推送。
- 断线时明确提示，任务保留在服务器，恢复后补齐。没有服务端领取成功确认前，不要重复拿货。
- 管理员可配置服务、配货和配送提醒时限。超时仅提醒，不会自动释放或重新派单。
- 管理员转交任务须填写原因，并先确认实物与原处理人；转交后原负责人不能完成该任务，新负责人会收到任务提醒。
- 只有管理员在实物已核对并归还后，才可“核实归还并召回”配送批次。召回会暂停新的配货与领取配送，核实后可恢复，或按原退款流程处理。
- 在途商品必须先核实，不能直接退款回库。已实际送达的数量不进入顾客可退款数量；未送部分退款后，配齐待取的相关批次会取消，剩余商品重新显示待配。
- 退款明确失败时，未完成订单继续暂停配货与领取。管理员核实顾客意愿后恢复，或重新处理退款；失败不会自动回库或放行配送。
- 订单或服务请求尚未完成、团购结果待确认或退款处理中时，不能结束桌台；会话尚未结束时不能改桌号，避免送错桌。

## 收银账单与小票

“订单管理 → 小票”打印指定订单，“桌台账单 → 查看账单 / 打印”汇总同次开台的首次点单、加单和团购；桌台管理也有“本桌账单”入口。原订单支付、退款和配送记录保留，不把新一轮开台的顾客合进旧账单。

拥有订单权限的收银员可预览并打印、查询任务回执及原版本补打；设备、图片和固定版式由超级管理员配置，打印结果人工核对由管理员 / 超级管理员处理。示例预览联动门店名称，也可在“抬头 → 小票店名”单独设置。打印状态不明确时不重复拿另一份任务重发，先核对实际出纸。

数据报表仅超级管理员可查看和导出，可设置下午至次日的营业时段。设备连接、图片范围、账务口径和 Excel 格式见 [小票、账单与营业报表说明](PRINTING-AND-BUSINESS-REPORTS.md)。

## 更新与验证

数据库升级为新增表和字段，保留现有金额、钱包、库存和账号。历史已完成订单补录送达数量，历史配货人未知时不编造负责人。旧备份恢复也会执行相同升级。上线前保留完整备份，并核对未完成订单及实物；恢复备份属于业务数据回退，恢复后必须核对实际已送达情况。

服务器仍使用 `bash scripts/manage.sh update`，宝塔托管完成后手动重启 Node 项目；若更新包含顾客小程序源码改动，还需在微信开发者工具重新上传和发布。仅后台打印、报表或运行时配置更新不要求重新上传小程序。

`npm test` 覆盖账号权限、桌台隔离、请求合并与重试、抢单、分批配送、旧事件补拉、转交、召回、退款数量，以及清台权限、未完成业务拦截和重试不会关闭新会话。浏览器验证使用独立临时数据库，不向真实门店发送测试需求。

## 收银交接与退款选择

“收银交接班”沿用收银点单权限，首次开班后启用现金班次控制。盘点期间暂停现金收支业务，非现金付款继续，接班确认时开启新班；交班不结束桌台、不改变任务负责人。退款默认不回库，停止配送和实物回库分别记录；未开封实物退回可按基础货品选择数量。具体步骤、差异处理及权限见 [单门店营业操作说明](SINGLE-STORE-OPERATIONS.md)。
