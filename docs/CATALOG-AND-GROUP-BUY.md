# 基础货品、套餐与收银团购登记

## 使用顺序

1. 超级管理员在“商品与库存”配置基础货品的单位、进货成本、补货线、目标库存、每箱数量。只用于套餐的货品选择“仅供套餐使用”。
2. 新建组合套餐，选择组成货品及每套数量，设置小程序售价、会员价、附加成本和参考总成本。计算成本 = 组成货品进货成本 × 数量 + 附加成本；参考总成本用于校核，不重复计入成本。
3. 管理员在“团购记录”新增团购套餐配置，选择美团 / 抖音、关联本店组合套餐、填写名称、参考售价与预计费率。无需平台套餐 ID、SKU 或开放平台密钥；系统自动生成本店配置标识，旧平台 ID 保留供历史追溯。
4. 收银员先在美团 / 抖音商家端完成真实核销，再在“收银点单 → 商品点单”中选择支付方式“团购核销”。查找顾客手机号、选择桌台与对应套餐，确认平台实际券金额，勾选已核实商家端核销成功后提交，无需登记券码。
5. 每次一张券对应一套固定套餐，按组成货品出库并进入现有服务工作台配货配送。顾客无需先扫码，收银可为有效桌台开台并绑定该顾客；订单保存顾客身份快照，顾客可在订单中查看。普通加购商品另行下单，同次开台归入同一账单。

收银团购下单沿用“收银点单”（`pos`）权限，获授权的普通店员也可办理，不需要额外 `group-buy` 权限或管理员角色。原“团购核销”菜单改称“团购记录”，保留原 `group-buy` 权限：管理员配置套餐、核对历史异常和同步撤销；实际到账仅超管登记。新建收银账号默认含收银点单、订单管理和团购记录，已有账号权限不自动改变。只有团购记录权限不能登记新订单，需另授收银点单。

旧版“套餐”分类商品不会自动转换为组合套餐，已有库存和历史订单保留；需要管理员确认实际包含的货品后配置。商品仍在购物车或未完成订单中时，不能转换类型。已建立团购配置的套餐不能修改组成；内容变化请新建组合套餐和团购配置，停用旧配置，保留历史快照。

## 库存与查询

- 基础货品保存账面库存和预占库存，可售 = 账面 − 预占。套餐可售数量为各组成货品 `可售 ÷ 每套用量` 向下取整后的最小值。多个套餐共用货品，其可售数量不能相加。
- 购物车、收银下单和团购兑换统一检查组成货品总需求，单品与多个套餐混购也不能超卖。
- 支付 / 收银登记成功记出库，送达时不重复扣库存。待支付订单和历史结果未确认的核销预占货品。
- 商品列表支持关键词、类型、低库存、缺货筛选；明细显示相关套餐、近 30 天各渠道消耗和库存流水，日期筛选最多展示 500 条。旧版没有记录的销售流水不进行猜测补录。
- 可按箱进货，按基础单位管理库存；CSV 可导出库存。批量盘点使用“货品 ID, 盘点数量”，先预览再提交，库存 / 预占变化会要求重新预览。盘点数量指**未分配的账面货品**，已支付但未送达的货品已出库，应单独核对待配货清单。
- 套餐订单保留组成版本、货品、单价和成本快照。服务工作台按组成货品配送，可分批。金额按整分钱分配，后台保留尾差产生的原价格明细；订单清单、服务工作台及每批配送清单按基础货品 ID 与单位合并，如啤酒 ×6，不把分摊行显示成多条 ×1。不同商品即使同名也不合并，不跨订单或配送批次合并；名称取下单时的组成快照。数量、总金额和成本均保持一致。已有订单也按该规则展示，不修改历史明细，不需要重新下单。
- 库存流水包括新订单出库、退款退回、赠送 / 报损、积分奖品、调整和盘点。赠送 / 报损和积分奖品请选择基础货品。

## 登记规则与结算

小程序不再提供团购查询和核销入口；后台“接口配置”不再展示美团 / 抖音密钥和启用开关，服务端不再调用两平台查券、核销或核销历史接口。即使服务器仍保留旧启用环境变量也不会生效。旧版小程序及后台核销 / 重查接口返回 HTTP 410 提示改用收银点单。此改动不会删除历史订单、券码、平台 ID、结算或未确认记录。

- 本地操作只登记商家端已核销的结果，并生成配送订单，不代替真实平台核销。请先检查套餐可售库存，再在商家端核销，避免库存不足时已核销无法配货。失败不会生成订单或部分扣库，必要时由员工补货或在原平台处理退款。
- 每次登记已线下核销的固定套餐一套，不收集券码，不混入普通商品，不支持代金券、次卡、多选套餐或一张券多次使用。实际券金额须明确填写、最多两位小数，不以参考售价自动冒充实际成交价。
- 团购订单不再收微信、现金或会员余额，不叠加会员折扣、优惠券或赠金。普通点单未提交清单会保留，切回其他支付方式可继续；额外商品另行支付。
- 提交、预占、出库、订单和配送事件在同一数据库事务中完成。同一请求重试仅返回原订单，避免重复出库；不同新请求视为独立登记。本地不收集券码，也不判断某张券是否已登记，服务员负责在商家端扫码核销及核对；旧待核对记录需先处理，避免重复补单。
- 新记录不保存券码，后台显示“线下已核销”；内部唯一编号只用于本地记录和重试，不充当平台券号。历史券码仍保留原有脱敏展示。券金额、预计结算和实际结算分开保存，未知到账金额不记为 0。预计结算按登记券金额与配置费率计算，仅为估算，不表示已到账。
- 实际结算由超管在“团购记录”填写累计到账金额和到账日期时间，按门店时区归属报表。修正累计金额保存差额调整，重复请求不再次计入；旧记录只有金额但没有到账日期时不猜测日期。
- 券金额计入对应消费销售，实际到账单独列为平台结算；核销记账不重复加入外部收款。商品毛利估算减实际商品净成本和赠送报损，尚未扣未记录的平台费用、房租和人工。跨日统计与 Excel 口径见 [小票、账单与营业报表说明](PRINTING-AND-BUSINESS-REPORTS.md)。

组合套餐在顾客清单和小票中按套计价，可展示包含的货品；基础货品库存流水按实际消耗数量展开，不把套餐价格再次加入组成商品收入。团购订单和本次开台的其他加单一起进入桌台消费账单，各来源订单及付款信息独立保留。

## 历史异常与撤销

旧版结果未知的券继续预占货品，移除在线功能不会自动释放或重新核销。管理员在“团购记录”核实原商家端状态：确认成功时填写平台凭证并生成一次配送订单，确认未核销时释放预占。原进程中断的处理中记录升级后归入待核对。已保存成功结果但订单未生成的旧记录，后台仍可本地恢复，不访问团购平台、不重复出库。结果待核对的桌台不能结束。

顾客不能用余额 / 微信退款接口退团购订单。需先在原平台撤销核销或退款，再由管理员在团购记录中填写平台凭证同步撤销；支持原平台已完成整券退款 / 撤销且无配送在途的订单，停止剩余配送并冲回团购收入一次；默认不回库，可逐项选择确认可售的基础货品回库，保留实际消耗成本。已交付货品回库须实际收回并确认未开封、未使用。平台部分退款自动分摊不在本版范围。本地撤销不替代原平台操作，后续下单仍需服务员确认实际有效的线下核销结果。

超级管理员在“账号管理 → 修改密码”中可直接设置管理员 / 店员密码，无需原密码，目标账号已有会话失效。已登录超级管理员修改自己的密码也无需旧密码，保留当前会话并注销其他设备；普通账号修改自己的密码仍需原密码。所有重置都有操作日志。

## 验证范围

测试使用独立临时数据库，覆盖共用库存、金额 / 成本快照、收银独立权限、手机号绑定、每次一套、无需券码与提交重试、库存不足原子回滚、旧接口不可启用、历史预占和本地恢复、平台撤销后的收入冲回及回库选择。小程序测试确认不再注册核销页面或发起相关请求。浏览器预览与测试不代替微信真机、实际商家端操作或真实结算验收。

退款不回库、部分基础货品回库及已送达实物退回的操作见 [单门店营业操作](SINGLE-STORE-OPERATIONS.md)。
