# 操作日志筛选、导出与清理

入口为“系统设置 → 操作日志”，仅超级管理员可查看、导出及清理，沿用原账号权限，不向管理员或服务员开放日志管理。

## 查询

- 默认查询门店时区最近 7 个自然日（含今天），可调整开始、结束日期及时间。沿用“数据报表”中的门店时区，与服务器系统时区无关。
- 开始时刻包含，结束时刻不包含；例如查询 10 月 19 日全天，填写 `2026-10-19 00:00` 至 `2026-10-20 00:00`。
- “搜索日志”匹配账号、操作名称、详情，最多 100 字，`%` 和 `_` 按普通文字搜索，不当作通配符。
- “全部时间”取消时间限制，保留当前关键词；也可只填写开始或结束时间。查询结果每页 20 / 50 条，时间相同时按日志 ID 排序。

## 导出 Excel

点击“导出筛选结果 Excel”，按按钮所在表单的时间及关键词生成全部匹配记录，不限当前页。单次最多 10000 条，超限需缩短范围或增加关键词；无结果时不生成空文件。

文件示例：`操作日志-202610190000-202610200000-a1b2c3d4.xlsx`。未指定起点时文件名使用“最早”，未指定终点时使用生成时刻；末尾 8 位为导出批次短编号，避免同一时间段的多份文件混淆；实际筛选条件和完整批次号在文件中列明。

| 工作表 | 内容 |
| --- | --- |
| 导出说明 | 文件名、导出批次、生成时间、门店时区、起止范围、关键词、原日志条数及清理规则 |
| 操作日志 | 日志 ID、时间、账号、操作、详情、详情分段；文本按文本格式保存，不执行公式 |

详情过长时按同一日志 ID 分成多行，保留完整文本；日志条数按原记录计，不按拆分后的 Excel 行数计。文件下载到操作人员的设备，不在服务器长期保存 Excel 副本。浏览器发起下载不等于文件已经保存，清理前须人工核对本地文件。

## 导出后选择清理

1. 下载、保存并打开 Excel 核对内容；如需完整追溯，另行保留数据库备份。Excel 不是完整业务备份，也没有通过此页面重新导入日志的入口。
2. 页面“本次已导出”显示文件名、条数和原筛选条件，即使之后查询其他范围，清理仍对应这个文件。点击“删除本次已导出的日志”。
3. 勾选已保存并核对文件的确认项，再点击“确认删除已导出日志”。这会永久删除此批原日志；导出本身不会自动删除。

清理按导出快照中的 ID、记录标识和内容校验执行，不重新按当前筛选删除：后来新增、补记的日志不会被包含；原日志内容发生变化时整批拒绝，须重新导出。重复提交返回原清理结果。导出、清理各自另留操作记录，包含账号、批次、原筛选、文件名和条数。

清理只涉及 `operation_logs`，不删除订单、支付、退款、库存、会员或收银班次数据。凭证仅本人可用，保存在数据库，重启后仍可继续；有效期 24 小时，每个账号只保留最近 5 批，超时 / 超出批数需重新导出。凭证只存 ID 和校验值，不另存一份日志全文，访问日志页面或导出时会清理过期凭证。完整刷新 / 关闭浏览器页面或重新登录后不再显示旧下载入口，需重新导出。

## 存储与维护

日志为文字记录，通常比图片小，但长期累计仍会增加数据库及备份体积。页面显示“匹配条数 / 日志总数”“业务数据库大小”“可复用空间”。数据库大小包含订单等全部业务数据，不能当作日志单独占用；不包含图片、备份和 SQLite 临时 WAL 文件。

删除日志后 SQLite 通常保留空闲页供后续写入复用，磁盘文件不一定立即变小。系统不在营业请求里自动执行数据库压缩，也不默认自动删除历史日志。确需缩小文件时，应在非营业时段先备份、停止写入，再由维护人员执行数据库整理；`VACUUM` 可能需要最多约两倍原库大小的空闲空间，见 [SQLite 官方说明](https://www.sqlite.org/lang_vacuum.html)。旧备份仍包含当时的日志，依照原备份保留计划管理，清理日志不会删除备份文件。

## 部署与验证范围

本次仅修改后台及服务端，无须重新发布顾客小程序。升级自动新增日志记录标识、时间索引和导出批次表，旧备份恢复后执行同样迁移；不改写既有业务记录。

自动测试使用临时数据库，覆盖门店时区及边界、关键词、分页、Excel 内容和长文本、权限、导出上限、快照清理、重试、日志被修改 / ID 重用时的保护和凭证过期。浏览器验证也使用演示数据；没有清理实际门店日志。
